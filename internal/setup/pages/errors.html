{{/* Errors on their own page: the request can't continue the flow in place. Each names what failed, why, and what to do; .AppsURL, when set, is the owner's App settings, where an App GitHub already created is deleted. */}} {{define "fail-spent-state"}}{{template "error-top" .}}

This link from GitHub was already used or has expired

GitHub's link back to setup works once and lasts an hour.

If setup shows the App as created, carry on there. Otherwise delete the App GitHub created in your App settings, then create it again from setup.

{{template "error-bottom" .}}{{end}} {{define "fail-other-browser"}}{{template "error-top" .}}

This browser didn't start that registration

Setup only accepts an App's key in the browser that sent it to GitHub, so it ignored this one.

Delete the App GitHub just created in your App settings, then create it again from setup in this browser.

{{template "error-bottom" .}}{{end}} {{define "fail-conversion"}}{{template "error-top" .}}

GitHub created the App but didn't hand over its key

Exchanging GitHub's one-time code for the App's id and private key failed. The exemplar-api log has GitHub's answer.

Delete the App in your App settings, then create it again from setup.

{{template "error-bottom" .}}{{end}} {{define "fail-key"}}{{template "error-top" .}}

The new App's private key didn't load

GitHub returned a key setup can't parse, so it can't look for the App's installation.

Delete the App in your App settings, then create it again from setup.

{{template "error-bottom" .}}{{end}} {{define "fail-stale-form"}}{{template "error-top" .}}

This page is out of date

Its form no longer matches setup's signing key, which changes when the exemplar-setup Secret is emptied or replaced.

Open setup again and repeat what you were doing.

{{template "error-bottom" .}}{{end}} {{define "fail-not-ready"}}{{template "error-top" .}}

That step isn't open yet

Setup needs the App created and installed, with exemplar-config, before this step.

Open setup again: it shows the step to do next.

{{template "error-bottom" .}}{{end}} {{define "fail-manifest"}}{{template "error-top" .}}

Setup couldn't build the App manifest

This is a bug in Exemplar; the exemplar-api log has the details.

Report it, with the log, at https://github.com/koblas/exemplar/issues.

{{template "error-bottom" .}}{{end}} {{/* .Secret: the Secret the cluster lacks. The manifests declare every Secret setup writes, empty, so exemplar-api's Role can name it. */}} {{define "fail-secret-missing"}}{{template "error-top" .}}

The {{.Secret}} Secret isn't in the cluster

Setup writes into Secrets the manifests create empty, and this one is missing, so the manifests weren't all applied (or the Secret was deleted since).

Apply your installation's manifests again (kubectl apply -k on your overlay), then open setup again.

{{template "error-bottom" .}}{{end}} {{define "fail-kube-api"}}{{template "error-top" .}}

exemplar-api couldn't reach its Secrets

The Kubernetes API refused or didn't answer when setup read or wrote the installation's Secrets. The exemplar-api log has its answer.

Check that the exemplar-api-setup Role and RoleBinding are in namespace {{.Namespace}}, and that the exemplar-api NetworkPolicy lets it reach the API server; then reload.
